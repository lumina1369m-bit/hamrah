# همراه — سورس پروژه

مخزن سورس پروژه‌ی «همراه» (پلتفرم اتصال مسافر نیازمند مترجم به مترجم همراه): سرور، اپ مسافر، اپ مترجم، پنل مدیریت، تست‌ها و مستندات.

## ساختار پوشه‌ها

| پوشه / فایل | محتوا |
|---|---|
| `server/` | سرور Node.js و پایگاه داده‌ی SQLite. فایل اصلی `server.js` است. |
| `server/test/` | تست‌های API و امکانات و شهرها و زمان‌بندی |
| `traveler/` | اپ مسافر (PWA) |
| `translator/` | اپ مترجم (PWA) و میز کار |
| `admin/` | پنل مدیریت (یک صفحه‌ی HTML) |
| `tests/` | تست‌های مرورگر (Playwright). اجرای همه: `./run_all.sh` |
| `legacy/` | دو فایل قدیمی که بیرون از انتشار نگه داشته شده‌اند و سرو نمی‌شوند |
| `docs/` | اسناد Word: سند جامع، سند اپ مترجم، بازبینی‌ها |
| `design/` | مرجع طراحی (خروجی ابزار Stitch) |
| `RELEASE_CHECKLIST.md` | چک‌لیست انتشار و تصمیم‌های ثبت‌شده |

## اجرای سرور

پیش‌نیاز: Node.js نسخه‌ی ۲۰ یا بالاتر.

```bash
cd server
npm install
HZ_DEV=1 HZ_ADMIN_PASSWORD=your-admin-password PORT=8080 node server.js
```

متغیرهای محیطی:

- `PORT`: پورت سرور (پیش‌فرض ۸۰۸۰ در تنظیمات فعلی).
- `HZ_ADMIN_PASSWORD`: رمز آغازین ورود به پنل مدیریت. بدون آن پنل فعال نمی‌شود. مدیر می‌تواند بعداً از داخل پنل (تب «تنظیمات ← تغییر رمز مدیر») رمز را عوض کند؛ رمز تازه به‌صورت هش‌شده در پایگاه داده ذخیره می‌شود و از آن پس همان معتبر است.
- `HZ_DEV=1`: حالت توسعه. کد ثابت پیامک `123456` و ورود آزمایشی مترجم فقط در این حالت فعال است. **در نسخه‌ی واقعی هرگز نگذارید.**
- `HZ_DOC_KEY`: کلید رمزنگاری مدارک مترجمان. در حالت غیرتوسعه **الزامی** است؛ بدون آن سرور اجرا نمی‌شود.

## اتصال پیامک (کد ورود)

لایه‌ی ارسال پیامک آماده است (`server/lib/sms.js`) و با متغیرهای محیطی فعال می‌شود؛ تا وقتی تنظیم نشده باشد، در حالت غیرتوسعه درخواست کد پاسخ `503 sms_provider_not_configured` می‌دهد.

- `HZ_SMS_PROVIDER`: `kavenegar` یا `webhook`
- `HZ_SMS_API_KEY`: کلید API ارائه‌دهنده (برای `webhook`، توکن Bearer اختیاری)
- `HZ_SMS_TEMPLATE`: فقط کاوه‌نگار؛ نام قالبی در پنل کاوه‌نگار که جای‌نگهدار کد دارد (پیش‌فرض `hamrah-otp`)
- `HZ_SMS_WEBHOOK_URL`: فقط حالت `webhook`؛ سرور بدنه‌ی JSON ‏`{ phone, code }` را به این آدرس پست می‌کند

فعال‌سازی بعدی فقط سه قدم است: ۱) ثبت‌نام و گرفتن کلید از ارائه‌دهنده، ۲) ساخت قالب پیامک کد در پنل او (برای کاوه‌نگار)، ۳) تنظیم متغیرهای بالا و راه‌اندازی دوباره‌ی سرور. توجه: پنل‌های داخلی فقط به شماره‌های ایرانی پیامک می‌فرستند؛ ورود مسافر خارجی با شماره‌ی غیرایرانی به ارائه‌دهنده‌ی بین‌المللی یا ورود ایمیلی نیاز دارد.
- `HZ_DB`: مسیر فایل پایگاه داده. پیش‌فرض `server/data/hamzaban.sqlite`.

بعد از اجرا:

- پنل مدیریت: `http://localhost:8080/admin/`
- اپ مترجم: `http://localhost:8080/translator/`
- اپ مسافر: `http://localhost:8080/traveler/`

## اجرای تست‌ها

```bash
pip install -r tests/requirements.txt
python3 -m playwright install chromium
cd tests
./run_all.sh
```

`run_all.sh` دو سرور موقت روی پورت‌های ۸۰۸۱ و ۸۰۸۲ بالا می‌آورد و با پایگاه داده‌ی موقت تست‌ها را اجرا می‌کند. تست‌های API جدا هستند:

```bash
cd server
BASE=http://127.0.0.1:8081 node test/api.test.js
```

بررسی خودکار گیت‌هاب علاوه بر چهار مجموعهٔ تست سرور، تست‌های Chromium برای گزینه‌های رزرو، پایان خدمت، کارت تمدید، پرداخت نقدی و فاکتور را روی سرور و پایگاه دادهٔ آزمایشی مستقل اجرا می‌کند. تست پایان خدمت دکمه‌های واقعی مسافر و مترجم را می‌زند: رد درخواست و ادامهٔ خدمت، قبول درخواست، و پایان زودهنگام توسط مسافر؛ در همهٔ حالت‌ها مبلغ کامل باید حفظ شود. تست `booking_options_ui.py` نیز هر سه ترجیح جنسیت را در رزرو فوری و زمان‌دار (فارسی، انگلیسی و عربی) با کلیک واقعی ثبت می‌کند؛ مدت، خودرو، تعداد مسافران، توضیحات، تعرفه و مبلغ ذخیره‌شده را بررسی می‌کند و در حالت فوری پذیرش توسط مترجم مناسب را می‌آزماید. فقط سرویس بیرونیِ نشانی در این تست جایگزین شده و ساعت مرورگر برای انتخاب زمان آینده در حالت زمان‌دار تنظیم می‌شود؛ سرور واقعی است. تست `service_clock_ui.py` بازیابی تایمر و مدت واقعی پس از بازکردن دوباره، تمدید با تأیید مترجم و بازیابی فاکتور با مبلغ توافق‌شده را بررسی می‌کند؛ برای شبیه‌سازی گذشت زمان فقط ساعت مرورگر جلو می‌رود و ساعت سرور تغییر نمی‌کند. تست `settlement_failure_ui.py` نیز رد پرداخت، قطع اتصال، نبود نشست و چند کلیک هنگام انتظار پاسخ را بررسی می‌کند: فاکتور تا ثبت معتبر پرداخت باز می‌ماند و پرداخت نقدی همچنان منتظر تأیید مترجم است. تست `payment_methods_ui.py` نیز هر چهار حالت فعال/غیرفعال نقدی و آنلاین را در فاکتور و فهرست رزروها بررسی می‌کند. دریافت ناموفق یا نامعتبر تنظیمات، پرداخت را می‌بندد؛ با تازه‌سازی موفق، روش مجاز دوباره انتخاب می‌شود. تنظیمات پیش از ثبت پرداخت دوباره از سرور خوانده می‌شوند؛ خاموش‌شدن روش انتخابی باعث تغییر خودکار روش همان درخواست نمی‌شود. عکس خطای این تست‌ها و لاگ سرور هنگام شکست به مدت ۷ روز ذخیره می‌شوند. تست‌های آنلاین فقط شبیه‌ساز موجود را بررسی می‌کنند و به معنی اتصال درگاه بانکی واقعی نیستند.

## نکته‌های امنیتی و انتشار

- پوشه‌ی `server/data` خالی است. پایگاه داده‌ی توسعه (با داده‌ی آزمایشی) در سورس نیست.
- `node_modules` در سورس نیست؛ با `npm install` ساخته می‌شود.
- کلید `HZ_DOC_KEY` و رمز مدیر را هرگز در کد نگذارید.
- جزئیات کامل وضعیت انتشار در `RELEASE_CHECKLIST.md` آمده است.

### ورود واقعی مسافر
ورود با ایمیل تا زمان اتصال سرویس واقعی غیرفعال است؛ کد ثابت یا پروفایل محلی، ورود موفق ایجاد نمی‌کند. مسیر شماره همراه فقط با پاسخ معتبر `/api/auth/verify` توکن می‌گیرد. در بازگشت به صفحهٔ ورود، نشست از `/api/auth/me` بررسی می‌شود و هویت ذخیره‌شده فقط برای همان شناسهٔ حساب استفاده می‌شود؛ پروفایل‌های قدیمی ممکن است یک‌بار نیاز به تکمیل دوبارهٔ هویت داشته باشند. دکمهٔ درج کد آزمایشی فقط پس از دریافت `dev: true` نمایش داده می‌شود و حتی در محیط توسعه، بررسی کد روی سرور است. تست سه‌زبانه: `tests/traveler_auth_ui.py`.

### خروج از حساب و نشست‌های دیگر
دکمهٔ «خروج» ابتدا `/api/auth/logout` را صدا می‌زند و فقط نشست همان دستگاه را روی سرور باطل می‌کند. «خروج از همهٔ دستگاه‌ها» با `/api/auth/logout-all` تمام نشست‌های حساب احرازشده (از جمله نشست فعلی) را باطل می‌کند؛ شناسهٔ هدف از مرورگر پذیرفته نمی‌شود و حساب‌های دیگر یا نقش جداگانهٔ همان شماره دست‌نخورده می‌مانند. تنها پس از پاسخ معتبر سرور، توکن، هویت و کش رزروهای همین مرورگر پاک می‌شوند؛ زبان انتخابی حفظ می‌شود. خطای شبکه/پاسخ نامعتبر، خروج موفق محسوب نمی‌شود و قابل تلاش دوباره است. دستگاه‌های مسافرِ باز، پس از پاسخ ۴۰۱ به درخواست بعدی (معمولاً همگام‌سازی هر ۵ ثانیه)، اطلاعات محلی را پاک می‌کنند و به ورود برمی‌گردند؛ دستگاه آفلاین تا اتصال دوباره چنین پاسخی دریافت نمی‌کند. تست چنددستگاهی در سه زبان: `tests/logout_sessions_ui.py`.

### قابلیت‌های فعال و غیرفعال حساب مسافر
حساب مسافر کارت بانکی نمونه یا نشان تأیید هویت بر پایهٔ `localStorage` نشان نمی‌دهد. بررسی گذرنامه، ذخیره/اتصال کارت بانکی و درخواست تغییر جنسیت یا شمارهٔ ورود هنوز گردش‌کار سروری ندارند؛ در رابط صریحاً غیرفعال‌اند و ثبت درخواست یا ارسال مدرک را شبیه‌سازی نمی‌کنند. پرچم‌های محلی قدیمی مانند `passport: pending/verified` و `cardsRemoved` مبنای وضعیت واقعی نیستند و در رابط نادیده گرفته می‌شوند. نام و عکس پروفایل همچنان در همان مرورگر ذخیره می‌شوند و این محدودیت کنار فرم نوشته شده است. پرداخت واقعی رزروها از فاکتور، بدون وابستگی به این بخش انجام می‌شود. تست سه‌زبانه: `tests/account_truth_ui.py`.

### ایمنی و تماس پشتیبانی مسافر
تماس امن، پیامک با مترجم و اشتراک ردیابی زنده هنوز پیاده‌سازی نشده‌اند و دکمه‌هایشان صریحاً غیرفعال‌اند. دکمه‌های پشتیبانی سریع، ایمنی نقشه و راهنمای اضطراری، پنجرهٔ راهنما را باز می‌کنند؛ هیچ هشدار اضطراری، تماس یا پیامکی خودکار ارسال نمی‌شود و در خطر فوری باید با خدمات اضطراری محل تماس گرفت. شمارهٔ `support_phone` از پنل مدیریت، با هر بازکردن یا تازه‌سازی از `/api/config` خوانده می‌شود. فقط شمارهٔ با قالب قابل قبول به پیوند `tel:` تبدیل می‌شود؛ انتخاب آن صرفاً شماره‌گیر دستگاه را باز می‌کند و تضمین اتصال تماس یا پاسخ‌گویی نیست. شمارهٔ خالی/نامعتبر و خطای دریافت، هیچ پیوند تماس قدیمی یا پیش‌فرضی باقی نمی‌گذارند. تست سه‌زبانه: `tests/traveler_support_ui.py`.

### حذف حساب مسافر با تأیید واقعی
حذف حساب فقط با نشست معتبر، عبارت تأیید به زبان جاری و پاسخ صریح `{ok: true}` از `DELETE /api/auth/account` موفق محسوب می‌شود. حذف صرفاً محلی یا موفقیت بر اساس پاسخ خالی/نامعتبر انجام نمی‌شود. تا پایان درخواست، کنترل‌های حذف و خروج مسدودند؛ خطا یا پایان مهلت ده‌ثانیه‌ای، امکان تلاش دوباره را حفظ می‌کند. رد درخواست به علت رزرو یا پرداخت باز، از سرور هم بررسی می‌شود. پس از تأیید، اطلاعات ورود و داده‌های خصوصی این مرورگر پاک و پیام تأیید در صفحهٔ ورود نمایش داده می‌شود؛ زبان انتخابی باقی می‌ماند. پاسخ دیررس مربوط به حساب قبلی، نشست تازه را پاک نمی‌کند. وعدهٔ فاقد پیاده‌سازی «حذف ظرف ۳۰ روز و نگهداری تاریخچه/فاکتورها» از این پنجره برداشته شده است؛ سیاست و منطق حذف سروری در این تغییر عوض نشده‌اند. تست سه‌زبانه: `tests/account_delete_ui.py`.

### ثبت و عملیات رزرو فقط با تأیید سرور
ثبت رزرو بدون نشست معتبر یا پاسخ معتبر سرور، رکورد محلی و موفقیت ساختگی ایجاد نمی‌کند. لغو از نقشه یا کارت رزرو، تلاش مجدد و تبدیل به زمان‌دار به همان شناسهٔ رزرو سروری متصل‌اند؛ تغییر صفحه پس از تأیید است. تلاش مجدد/تبدیل، وضعیت تازه را هم از سرور می‌خوانند. درخواست‌های هم‌زمان روی یک رزرو مسدود و درخواست‌های معلق پس از ده ثانیه متوقف می‌شوند؛ پاسخ قدیمی همگام‌سازی یا حساب قبلی، نتیجهٔ تازه را بازنویسی نمی‌کند. در خطا یا مهلت تمام‌شده، نتیجهٔ قطعی ادعا نمی‌شود و باید پیش از تکرار ثبت، فهرست رزروها بررسی شود. سابقه‌های محلیِ فاقد شناسهٔ سروری فقط خواندنی‌اند و تایمر مرورگر به‌تنهایی «مترجم پیدا نشد» یا «لغو شد» تولید نمی‌کند.
درصد کارمزد لغو فقط از پاسخ سرور نمایش داده می‌شود و به معنی برداشت بانکی نیست. **پس از ثبت کد امنیتی و شروع خدمت، لغو ممنوع است**؛ مسافر همچنان می‌تواند پایان زودهنگام با مبلغ کامل توافق‌شده را انتخاب کند. تست‌های API و `tests/booking_actions_ui.py` این موارد را پوشش می‌دهند. تست مرورگر جدید به سرور مستقلِ توسعه با `HZ_TIME_SCALE=0.01` نیاز دارد (پیش‌فرض پورت ۸۰۸۲؛ قابل تغییر با `BOOKING_ACTION_BASE`)؛ CI و `tests/run_all.sh` آن را آماده می‌کنند.

### کنترل خدمت بدون شروع، پایان یا تمدید ساختگی
دکمه‌های اعلام رسیدن، بررسی شروع، پایان، قبول/رد پایان مترجم و تمدید، به شناسهٔ همان خدمتِ روی صفحه وصل‌اند؛ اولین سابقهٔ مرورگر به‌جای آن انتخاب نمی‌شود. پیش از اقدام، رزرو تازه از سرور خوانده می‌شود. کد امنیتی فقط از همان رزرو معتبر نمایش داده و تایمر فقط از زمان شروع واقعی سرور فعال می‌شود؛ نبود رزرو/نشست، تایمر و فاکتور محلی یا تمدید نمایشی ایجاد نمی‌کند.
پایان و قبول/رد آن، تأیید صریح و وضعیت تازهٔ سرور می‌خواهند. تمدید فقط با رسید معتبر درخواست و وضعیت «منتظر مترجم» پذیرفته می‌شود؛ تا قبول مترجم، مدت/مبلغ تغییر نمی‌کنند. عملیات یک رزرو بین کارت و تایمر قفل مشترک و مهلت ده‌ثانیه‌ای دارند؛ خطا/پاسخ نامعتبر یا پاسخ حساب قبلی باعث موفقیت کاذب نمی‌شود. مترجم نیز پس از شروع نمی‌تواند با «لغو مأموریت» خدمت را قطع یا به دیگری واگذار کند؛ باید درخواست پایان بدهد و مسافر بپذیرد. پایان زودهنگام خود مسافر همچنان با مبلغ کامل است. تست: `tests/service_actions_ui.py` در فارسی، انگلیسی و عربی.

### کنترل خدمت در اپ مترجم با تأیید وضعیت سرور
ثبت کد شروع، درخواست پایان و قبول/رد تمدید، قبل و بعد از اقدام وضعیت خصوصی همان مأموریت/درخواست را از سرور می‌خوانند؛ پاسخ موفق اولیه به‌تنهایی کافی نیست. مدت، مبلغ، سهم مترجم و زمان شروع با تصمیم ثبت‌شده تطبیق داده می‌شوند. نمای خصوصی فقط برای مترجم همان رزرو است و کد امنیتی مسافر را برنمی‌گرداند.
کنترل‌های تکراری تقویم و میز کار و کارت تمدید برای یک رزرو قفل مشترک و مهلت ده‌ثانیه‌ای دارند. پاسخ نشست قبلی، پاسخ ناقص، خطای شبکه یا تمدید منقضی پیام موفقیت نمی‌سازند؛ در نتیجهٔ نامشخص باید وضعیت را بررسی کرد، نه اینکه عملیات خودکار تکرار شود. درخواست پایان مترجم همچنان فقط درخواست است و تا تأیید مسافر خدمت ادامه دارد؛ مسافر می‌تواند هر زمان با مبلغ کامل پایان دهد. آزمایش اختصاصی: `tests/translator_service_actions_ui.py`، به‌همراه بررسی دسترسی و انقضا در تست‌های API و زمان‌بندی. این بخش ادعای تکمیل بررسی سایر کنترل‌های حساب، پیشنهادها یا پرداخت مترجم را ندارد.

### تأیید دریافت نقدی و اختلاف در اپ مترجم
دکمه‌های دریافت نقدی و اختلاف، مبلغ/سهم و وضعیت خصوصی همان رزرو را پیش و پس از ثبت از سرور می‌خوانند. رسید صریح باید با تأیید واقعی دریافت، وضعیت «تسویه‌شده» یا «اختلاف ثبت‌شده» تطبیق داشته باشد؛ ناپدیدشدن کارت یا پاسخ ۲۰۰ به‌تنهایی تأیید پرداخت نیست. ثبت دریافت مترجم با تسویهٔ قطعی یکی نیست: تسویه فقط با تأیید هر دو طرف است و ثبت اختلاف به‌معنی واریز یا بررسی انجام‌شدهٔ پشتیبانی نیست.
این دو دکمه قفل مشترک، مهلت ده‌ثانیه‌ای و حفاظت نشست دارند؛ بازسازی کارت با نظرسنجی قفل را باز نمی‌کند و پاسخ قدیمی، کارتِ تسویه‌شده را برنمی‌گرداند. فهرست ناقص/نامعتبر کنترل‌های قدیمی را حذف و امکان دریافت دوباره را نشان می‌دهد. تست: `tests/translator_cash_actions_ui.py`. این تغییر اتصال بانکی، پیامک یا پرداخت تازه‌ای ایجاد نمی‌کند و تنظیمات مدیر را تغییر نمی‌دهد.

### آمادگی مترجم فقط از وضعیت واقعی سرور
کلید آنلاین/آفلاین از `localStorage.shift` بازیابی یا خوش‌بینانه روشن نمی‌شود. خواندن خصوصی `GET /api/translator/online` وضعیت مؤثر و اجازهٔ دریافت مأموریت را برمی‌گرداند؛ ثبت تغییر به رسید بولی صریح و بازخوانی همان وضعیت نیاز دارد. درخواست PATCH مقدار غیربولی را رد می‌کند تا مقدارهایی مثل رشتهٔ «true» نتوانند محدودیت مدیر را دور بزنند.
در خطا یا نتیجهٔ نامشخص، وضعیت «نامشخص» و امکان بررسی مجدد نمایش داده می‌شود؛ بررسی مجدد فقط GET است و عملیات نامطمئن را تکرار نمی‌کند. کلیدها قفل مشترک و مهلت ده‌ثانیه‌ای دارند؛ پاسخ حساب قبلی در حساب فعلی اعمال نمی‌شود. بررسی دوره‌ای/بازگشت به صفحه خاموش‌شدن قابلیت توسط مدیر را بازتاب می‌دهد؛ روشن‌شدن قابلیت مترجم را خودکار آنلاین نمی‌کند. تغییر آمادگی جنسیت یا تنظیمات تطبیق را از کش مرورگر بازنویسی نمی‌کند. آزمایش: `tests/translator_presence_ui.py`؛ کش مترجم v26.

### پذیرش و رد پیشنهاد مأموریت بدون موفقیت کاذب
هر دو تصمیم به شناسهٔ همان پیشنهاد و رزرو متصل‌اند. پیش از اقدام، وضعیت خصوصی پیشنهاد، مهلت و سهم مترجم خوانده می‌شوند؛ رسید صریح و بازخوانی تصمیم ثبت‌شده لازم است. پذیرش افزون بر این، وجود مأموریت واقعی همان رزرو با همان سهم را بررسی می‌کند؛ ناپدیدشدن کارت از فهرست به‌تنهایی اثبات پذیرش یا رد نیست.
دو تصمیم قفل مشترک، مهلت ده‌ثانیه و حفاظت نشست دارند. بازسازی کارت با نظرسنجی قفل را باز نمی‌کند و فهرست قدیمی تصمیم ثبت‌شده را برنمی‌گرداند. فهرست خراب، کارت‌های قدیمی را حذف و دریافت دوباره را ممکن می‌کند. ردِ پس از انقضا مانند پذیرش دیرهنگام پاسخ ۴۱۰ می‌گیرد. نمای خصوصی فقط برای مترجمی است که پیشنهاد به او داده شده و کد، جنسیت، شماره مسافر یا مبلغ کل را افشا نمی‌کند. این مرحله رضایت تغییر مأموریت یا لغو قبل از شروع را بازطراحی نمی‌کند. آزمون: `tests/translator_offer_actions_ui.py`؛ کش مترجم v27.

### رضایت واقعی مترجم برای تغییر مأموریت
پذیرش و رد تغییر زمان، محل، مدت و سایر مشخصات، به همان درخواست و رزرو روی صفحه متصل‌اند. پیش از ثبت، مشخصات فعلی مأموریت و متن خصوصی درخواست خوانده و با تغییرهای نمایش‌داده‌شده تطبیق داده می‌شوند. پس از رسید صریح، تصمیم ثبت‌شده و تمام مشخصات مأموریت دوباره بررسی می‌شوند: پذیرش باید دقیقاً همان تغییرها را اعمال کرده باشد؛ رد باید مشخصات را دست‌نخورده نگه دارد. یادداشتِ همراه درخواست هم روی کارت دیده می‌شود.
ثبت پذیرش و اعمال تغییر در یک تراکنش پایگاه داده انجام می‌شوند؛ مأموریت پایان‌یافته قابل تغییر نیست و ردِ منقضی/تکراری موفق اعلام نمی‌شود. نمای خصوصی درخواست فقط برای مترجم همان مأموریت است و کد امنیتی مسافر را برنمی‌گرداند. قفل مشترک با کنترل‌های خدمت، مهلت ده‌ثانیه، جداسازی پاسخ حساب قبلی و جلوگیری از بازگشت فهرست قدیمی برقرارند. خطا یا پاسخ ناقص، نتیجهٔ قطعی یا تکرار خودکار عملیات ایجاد نمی‌کند.
این مرحله قیمت‌گذاری را بازطراحی نمی‌کند: مانند رفتار قبلی `applyChanges`، مبلغ و سهم ثبت‌شده با تغییر مشخصات دوباره محاسبه نمی‌شوند. اعتبارسنجی نمای مأموریت با دامنهٔ موجود تغییر مدت (۱ تا ۲۴ ساعت، از جمله مقدار اعشاری) هماهنگ شده تا کنترل شروع خدمت پس از یک تغییر مجاز از کار نیفتد؛ محدودیت ثبت اولیه و تمدید عوض نشده است. آزمون اختصاصی: `tests/translator_change_actions_ui.py`؛ بررسی دسترسی، تاریخچه، پایان و انقضا در آزمون‌های API و زمان‌بندی؛ کش مترجم v28.

### لغو واقعی مأموریت مترجم، فقط پیش از شروع
دکمهٔ لغو از کنترل مشترک مأموریت استفاده می‌کند: وضعیت خصوصی همان رزرو پیش از اقدام خوانده می‌شود و پس از رسید صریح، تاریخچهٔ خصوصی لغو باید ثبت واقعی و پایان تخصیص به مترجم فعلی را تأیید کند. ناپدیدشدن کارت یا پاسخ ۲۰۰ به‌تنهایی کافی نیست. ثبت تاریخچه، آزادکردن مأموریت و کم‌شدن امتیاز در یک تراکنش‌اند؛ تلاش تکراری امتیاز را دوباره کم نمی‌کند.
این تاریخچه فقط برای همان مترجم است؛ بعد از تخصیص به مترجم دیگر نیز بدون نمایش اطلاعات مسافر یا مترجم بعدی قابل بررسی می‌ماند. جزئیات خصوصی مأموریت پس از واگذاری برای مترجم قبلی بسته‌اند. قفل مشترک با شروع/پایان/تمدید و تصمیم تغییر، مهلت ده‌ثانیه، جداسازی نشست و جلوگیری از بازگشت فهرست قدیمی برقرارند؛ خطا/پاسخ گم‌شده نتیجهٔ قطعی یا تکرار خودکار POST نمی‌سازد.
لغو پیش از شروع، مطابق سیاست قبلی تا ۵ امتیاز کم می‌کند و قیمت رزرو مسافر را تغییر نمی‌دهد؛ پیدا شدن مترجم جایگزین تضمین نمی‌شود. رزرو زمان‌دار دور به انتظار زمان تطبیق برمی‌گردد. **پس از شروع، لغو ممنوع است** و مترجم همچنان باید درخواست پایان بدهد و مسافر بپذیرد. آزمون: `tests/translator_cancel_actions_ui.py`؛ دسترسی/حریم خصوصی/قیمت/تکرار/امتیاز در API و انتظار زمان‌دار در آزمون زمان‌بندی؛ کش مترجم v29.

### ایمنی و پشتیبانی مترجم، بدون هشدار یا تماس ساختگی
بخش پشتیبانی مترجم فقط راهنماست: بازکردن آن هیچ موقعیت، هشدار اضطراری یا درخواست اعزامی ارسال نمی‌کند. ادعاهای نمایشیِ ارسال موقعیت، زمان رسیدن گشت، اعزام اسکورت، تماس برقرارشده و پشتیبانی تضمینی ۲۴ساعته از این بخش حذف شده‌اند. اعزام میدانی صریحاً غیرفعال است؛ در خطر فوری باید با خدمات اضطراری محل تماس گرفت، نه اینکه منتظر اقدام برنامه ماند.
شمارهٔ پشتیبانی در هر بازکردن یا دریافت دوباره، از `GET /api/config` و تنظیمات مدیر خوانده می‌شود. شمارهٔ معتبر به پیوند `tel:` تبدیل می‌شود؛ انتخاب آن فقط شماره‌گیر دستگاه را باز می‌کند و اتصال یا پاسخ‌گویی تضمین نمی‌شود. شمارهٔ ثابت/نمونه یا کش مرورگر جایگزین تنظیمات نیست. شمارهٔ خالی/نامعتبر، خطای دریافت و مهلت ده‌ثانیه‌ایِ پاسخ یا بدنه، پیوند قدیمی باقی نمی‌گذارند. بستن، Escape یا رفتن به بخش دیگر، پیوند را پاک و پاسخ دیررس را بی‌اثر می‌کند.
آزمون موبایل و دسکتاپ: `tests/translator_support_ui.py`؛ تنظیمات واقعی مدیر، شماره‌های فارسی/عربی، قالب‌های نامعتبر، خطای شبکه/HTTP/JSON، درخواست هم‌زمان، پاسخ قدیمی و timeout بدنه بررسی می‌شوند. هیچ بانک، پیامک، اعزام یا سرویس اضطراری تازه‌ای متصل نشده است؛ سایر بخش‌های حساب و مدارک مترجم در این گام ممیزی نشده‌اند. کش مترجم v30.
